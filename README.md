# Chat App

A real-time chat app built with React and Firebase. You sign in with Google, create chat rooms, invite people by email or link, and messages show up live.

**Live:** https://chat-react-app-feb57.web.app/ (sign in with a Google account)

## Features

- **Google sign-in** through Firebase Authentication (popup).
- **Chat rooms:** create a room by name. The home page lists every room your email belongs to.
- **Real-time messages:** messages are stored in Firestore and stream in through `onSnapshot`, ordered by time. Your own messages are styled differently from other people's.
- **Sharing:** in a room, **Share** lets you add a member by email or copy the room link. Someone who opens the link and isn't a member yet gets a "You have been invited to join" screen with a **Join Now** button.

## Run it

Prerequisites: Node.js and npm. Tested with Node 22.22 / npm 10.9. No `NODE_OPTIONS=--openssl-legacy-provider` flag is needed.

```bash
npm ci
npm start          # dev server at http://localhost:3000
```

The app talks to the existing Firebase project `chat-react-app-feb57`. Its web config is in `src/utils/firebase.js`. Firebase web config is meant to be public; access is controlled by Firebase Auth and Firestore security rules. `localhost` is an authorized domain, so Google sign-in works from the dev server too.

Production build:

```bash
npm run build      # outputs to build/
npx http-server build -p 8080   # or any static file server
```

`npm run build` prints ESLint warnings (unused imports) but finishes. With `CI=true` set, Create React App treats warnings as errors, so use `CI=false npm run build` in CI.

### Use your own Firebase project

1. Create a Firebase project and add a web app.
2. Enable **Authentication → Sign-in method → Google**.
3. Create a **Cloud Firestore** database.
4. Replace `firebaseConfig` in `src/utils/firebase.js` with your app's config, and change the project ID in `.firebaserc`.

Firestore data model used by the code:

```
chats/{chatId}                    { chatName, owner, members: [email, ...] }
chats/{chatId}/messages/{msgId}   { content, chatId, createdAt, user }   // user = display name
```

The security rules are not in this repo. Who can read or join a room depends entirely on the rules set in the Firebase console.

### Deploy

`firebase.json` serves `build/` as a single-page app. With the [Firebase CLI](https://firebase.google.com/docs/cli) logged in to an account with access to the project:

```bash
npm run build
firebase deploy --only hosting
```

(Not run here, because it needs the project owner's Firebase login.)

The GitHub Actions workflows in `.github/workflows/` were generated by the Firebase CLI and deploy on pushes to `master` and on pull requests. They have no `npm ci && npm run build` step, so they try to deploy a `build/` folder that doesn't exist in a fresh checkout.

## Project structure

```
src/
  App.js                    routes (/, /create/, /chats/?chatId=...) and sign-out
  utils/firebase.js         Firebase app, Auth (Google provider) and Firestore setup
  utils/ChatDataObjects.js  shapes of chat and message documents
  pages/SignIn.js           Google sign-in screen
  pages/SelectChat.js       list of your chats
  pages/CreateChat.js       create a chat by name
  pages/ChatPage.js         messages, join screen, share modal
  components/               Messages, Message, TextBox, ChatHeader, ShareModal, ChatSelectCard, SignOut
firebase.json, .firebaserc  Firebase Hosting config
.github/workflows/          Firebase Hosting deploy workflows
```
